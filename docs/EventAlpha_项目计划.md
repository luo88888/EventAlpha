# 🎯 EventAlpha 项目计划

## 🧭 1. 项目定位

EventAlpha 是一个热点事件驱动的投资研究辅助系统，面向投资者、研究员和投资机构，帮助用户完成从热点事件发现、信息验证、金融市场影响分析、事件追踪到结果复盘的完整流程。

⚠️ 系统只提供事件研究、影响分析和风险提示，不直接给出买入、卖出、目标价或保证收益等投资指令。

## 🎯 2. 建设目标

### 💼 2.1 业务目标

- 🌍 自动发现全球重要热点事件，包括战争、加息/降息、贸易摩擦、关税、选举、地震、科技突破、产业政策、公司公告等。
- 🔎 判断事件是否真实、是否重要、是否具有市场影响。
- 📈 分析事件可能影响的行业、资产、公司和市场变量。
- 🧠 为用户提供可解释的因果推理链，而不是只给结论。
- 🔄 通过后续行情表现复盘历史判断，沉淀有效经验并修正错误逻辑。

### 📦 2.2 产品目标

- 🃏 提供事件卡片、复盘卡片、每日早报和事件详情页。
- 🔔 支持用户订阅关注行业、资产或主题。
- 🚨 支持紧急事件推送。
- 🔌 支持后续扩展为 Web 控制台、微信服务号、企业微信、Telegram 或机构 API 服务。

### ⚙️ 2.3 技术目标

- 📡 建立多源信息采集能力。
- 🏗️ 建立结构化事件抽取与去重聚类能力。
- 📊 建立可信度评分、事件重要性评分和市场影响评分体系。
- 🤖 建立多 Agent 协作流程。
- 📒 建立预测账本和自动复盘机制。
- 📚 建立可持续更新的知识库、规则库和资产映射库。

## 🏛️ 3. 总体架构

```text
📡 数据采集层
  新闻 / 公告 / 社交媒体 / 研报 / 行情
        |
🔧 事件处理层
  抽取 / 结构化 / 聚类 / 去重
        |
🔍 可信度验证层
  多源确认 / 官方核验 / 来源评分 / 风险标记
        |
🧠 推理分析层
  事件评分 / 因果链 / 历史类比 / 伪相关过滤
        |
📊 市场验证层
  资产映射 / 行情验证 / 异动检测
        |
🔄 复盘学习层
  预测账本 / 自动复盘 / 错误归因 / 规则更新
        |
🖥️ 产品服务层
  事件卡片 / 复盘卡片 / 日报 / API / 推送
```

## 📋 4. 阶段任务规划

## 🌱 阶段一：项目基础与事件卡片 MVP

### 🎯 阶段一目标

完成最小可用闭环，让系统能够采集新闻、抽取事件、分析影响并生成事件卡片。

### 📦 阶段一核心任务

- 🏗️ 搭建项目代码骨架。
- 🗄️ 设计基础数据库表结构。
- 📡 接入第一批稳定信息源，如 RSS、公开新闻 API、公告源。
- 📥 实现原始新闻入库。
- 🤖 实现事件抽取 Agent，将新闻转成结构化事件。
- 🔗 实现事件去重和初步聚类。
- ⭐ 实现可信度评分和事件重要性评分。
- 🧠 实现基础因果链分析。
- 🗺️ 实现行业、资产和公司初步映射。
- 🃏 生成事件卡片。
- 📒 建立初版预测账本。

### 🔧 阶段一建议交付物

- 🖥️ 后端服务基础框架。
- 🗄️ 数据库表：`raw_news`、`events`、`event_sources`、`event_scores`、`predictions`。
- ⏰ 定时新闻采集任务。
- 📋 事件卡片 JSON 输出。
- 🌐 简单 Web 页面或接口，用于查看事件列表和事件详情。

### ✅ 阶段一验收标准

- 📥 系统可以每天自动采集新闻。
- 🏗️ 系统可以从新闻中抽取结构化事件。
- 🃏 系统可以生成包含标题、摘要、可信度、事件级别、因果链、影响资产和风险提示的事件卡片。
- 📒 系统可以把每次判断写入预测账本。

## 📊 阶段二：市场数据验证与自动复盘

### 🎯 阶段二目标

接入行情数据，让系统能够验证事件发生后的市场表现，并自动复盘之前的判断。

### 📦 阶段二核心任务

- 📈 接入 A 股、港股、美股、商品、外汇或宏观数据源。
- 🗄️ 建立市场数据表。
- 📐 实现资产价格变化、成交量变化、相对基准表现计算。
- 🔄 实现事件影响资产的 T+1、T+3、T+7、T+30 复盘。
- 🃏 实现复盘卡片生成。
- 🏷️ 实现错误归因分类。
- 📝 将复盘结果写入复盘知识库。

### 🔧 阶段二建议交付物

- ⏰ 行情数据采集任务。
- 🗄️ 数据库表：`market_prices`、`reviews`、`review_metrics`。
- 🤖 自动复盘任务。
- 🌐 复盘卡片接口或页面。
- 📏 初版错误归因规则。

### ✅ 阶段二验收标准

- ⏰ 系统可以按计划自动触发复盘。
- 📊 系统可以计算预测资产在指定窗口内的涨跌幅和超额收益。
- 🎯 系统可以判断原始方向是否大致正确。
- 🏷️ 系统可以输出错误归因，如资产映射错误、市场提前反映、事件重要性高估、时间窗口错误等。

## 🤖 阶段三：多 Agent 协作与分析质量提升

### 🎯 阶段三目标

把单条流水线升级为多 Agent 协作系统，提高验证、推理和过滤能力。

### 📦 阶段三核心任务

- 🔗 引入 Agent 编排框架，如 LangGraph。
- 🧩 拆分核心 Agent：
  - 📡 Information Scout Agent：信息采集。
  - 🏗️ Event Extraction Agent：事件抽取。
  - 🔗 Event Clustering Agent：事件聚类。
  - 🔍 Credibility Verification Agent：可信度验证。
  - ⭐ Event Scoring Agent：事件评分。
  - 🧠 Causal Reasoning Agent：因果链推理。
  - 📜 Historical Analogy Agent：历史案例对比。
  - 🚫 Anti-Spurious Reasoning Agent：伪相关过滤。
  - 🗺️ Market Mapping Agent：资产映射。
  - 📊 Market Data Verification Agent：市场验证。
  - 🃏 Card Generation Agent：卡片生成。
  - 🔄 Review & Learning Agent：复盘学习。
- 📚 建立历史事件库。
- 📏 建立因果规则库。
- 🗺️ 建立资产映射库。
- ⭐ 建立来源可信度库。

### 🔧 阶段三建议交付物

- 📋 Agent 编排流程图。
- 📡 Agent 输入输出协议。
- 🔍 历史案例检索能力。
- 🚫 伪相关过滤规则。
- ⚙️ 可配置的事件评分模型。

### ✅ 阶段三验收标准

- 🧩 每个 Agent 有清晰职责和稳定输入输出。
- 🧠 系统可以解释事件影响市场的关键因果链。
- 📜 系统可以检索历史同类事件作为参考。
- ⚠️ 系统可以标记低证据、长链条、弱相关或可能已被市场提前反映的推理。

## 🔄 阶段四：学习闭环与规则自我修正

### 🎯 阶段四目标

让系统从复盘结果中学习，持续优化事件评分、资产映射、因果规则和来源权重。

### 📦 阶段四核心任务

- 📒 建立完整预测账本。
- 📚 建立复盘知识库。
- ⚙️ 设计规则更新机制。
- 📊 根据复盘结果调整事件类型权重、来源权重、资产映射权重和因果链权重。
- ✍️ 增加人工反馈入口。
- 🏷️ 增加规则版本管理。
- 📐 建立模型表现评估指标。

### 🔧 阶段四建议交付物

- 🗄️ 数据库表：`causal_rules`、`asset_mappings`、`source_reliability`、`rule_versions`、`user_feedback`。
- 🤖 规则更新任务。
- 📝 规则变更记录。
- 📊 复盘表现看板。

### ✅ 阶段四验收标准

- 💡 系统可以基于复盘结果生成规则调整建议。
- 📝 系统可以记录规则变更前后的效果。
- 🔍 系统可以识别长期低准确率的信息源、事件类型或资产映射。
- 🔄 系统可以形成"发现 → 判断 → 复盘 → 归因 → 更新"的闭环。

## 🗄️ 6. 核心数据表规划

### 📥 `raw_news`

存储原始新闻、公告、社交媒体内容和来源信息。

### 📋 `events`

存储结构化事件，包括事件类型、主体、时间、地点、状态、摘要和生命周期状态。

### 🔗 `event_sources`

记录每个事件对应的信息来源，用于可信度验证。

### ⭐ `event_scores`

存储事件可信度、重要性、影响范围、新鲜度和可交易性评分。

### 📒 `predictions`

预测账本，记录每次事件分析时对资产、方向、时间窗口和置信度的判断。

### 📈 `market_prices`

存储行情数据，用于后续验证。

### 🔄 `reviews`

存储复盘结论、实际表现和错误归因。

### 📏 `causal_rules`

存储可复用的因果规则。

### 🗺️ `asset_mappings`

存储事件类型到行业、板块、公司和资产的映射关系。

### ⭐ `source_reliability`

存储信息源在不同领域的历史可靠性评分。

## ⚠️ 8. 风险与应对

### 📡 数据源不稳定

优先接入稳定 RSS、公告源和正规 API，减少早期爬虫依赖。

### 🤖 大模型幻觉

要求模型输出证据来源、因果链和不确定性，并通过可信度验证 Agent 与伪相关过滤 Agent 进行约束。

### 🗺️ 资产映射过度发散

先建立人工维护的资产映射库，再逐步引入模型辅助扩展。

### ⚖️ 投资合规风险

所有输出必须是研究辅助和风险提示，不输出明确买卖建议、目标价、收益承诺或杠杆建议。

### 📊 复盘指标失真

复盘时同时计算绝对收益、相对收益、行业基准和大盘基准，避免把市场整体波动误判为事件影响。

## 🚀 10. 第一版 Demo 场景

建议第一版 Demo 使用"AI 芯片出口管制"或"中东冲突升级"作为样例事件。

### 🔄 Demo 流程

```text
📥 采集新闻
  -> 🏗️ 抽取结构化事件
  -> 🔍 多源验证
  -> ⭐ 事件评分
  -> 🧠 生成因果链
  -> 🗺️ 映射影响行业和资产
  -> 🃏 生成事件卡片
  -> 📒 写入预测账本
  -> 🔄 T+1/T+7 自动复盘
  -> 🃏 输出复盘卡片
```

### ✅ Demo 成功标准

- 👀 用户能看到系统如何从一条新闻生成完整事件卡片。
- 💡 用户能看到系统为什么认为某些行业或资产会受影响。
- 📊 用户能看到系统如何在后续用市场数据验证原始判断。
- 🔄 用户能看到系统如何归因错误并更新规则。
