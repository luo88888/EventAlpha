# 📁 EventAlpha 项目目录结构说明

> 基于 [EventAlpha_MVP一周项目计划.md](EventAlpha_MVP一周项目计划.md) 的四层架构建立。
>
> 架构分层：📡 数据采集层 / ⚙️ 事件处理层 / 🧠 推理分析层 / 🖥️ 产品服务层
>
> 技术栈：后端 **Python FastAPI** + 数据库 **SQLite（起步，可迁移 PostgreSQL）** + 前端 **Next.js/React**。
>
> 说明：当前仓库只创建了目录骨架，**不含任何源代码文件**，便于按 Day 1-7 排期逐步填充。

## 🌳 完整目录树

```text
EventAlpha/
├── backend/                        # 🖥️ 后端服务（FastAPI）
│   ├── app/
│   │   ├── main.py                 # 应用入口：挂载路由、定时任务、启动事件
│   │   ├── api/                    # 产品服务层：对外接口
│   │   │   └── v1/                 #   API v1 版本目录
│   │   ├── collectors/             # 📡 数据采集层：RSS/公开新闻源采集
│   │   ├── processors/             # ⚙️ 事件处理层：抽取/结构化/去重
│   │   ├── analysis/               # 🧠 推理分析层：评分/影响/因果链/风险提示
│   │   ├── models/                 # SQLAlchemy ORM 模型（对应数据表）
│   │   ├── schemas/                # Pydantic 请求/响应模型
│   │   ├── services/               # 通用服务，如 LLMService（统一封装大模型调用）
│   │   ├── jobs/                   # 定时/手动任务：采集、抽取、分析任务编排
│   │   └── core/                   # 基础设施：配置、数据库连接、日志、依赖注入
│   ├── alembic/                    # 数据库迁移工具
│   │   └── versions/               #   迁移脚本
│   ├── tests/                      # 测试
│   │   ├── unit/                   #   单元测试
│   │   ├── integration/            #   集成测试（接口、数据库、全链路）
│   │   └── samples/                #   测试用新闻样例（演示与回归用）
│   ├── config/                     # 配置文件目录
│   │   └── prompts/                #   大模型 Prompt 模板（事件抽取、影响分析）
│   └── pyproject.toml              # Python 项目依赖与元数据
├── frontend/                       # 🎨 前端应用（Next.js/React）
│   ├── app/                        # Next.js App Router
│   │   └── events/
│   │       └── [id]/               #   事件详情动态路由
│   ├── components/                 # 可复用 UI 组件（事件卡片等）
│   ├── lib/                        # API 客户端、工具函数
│   └── public/                     # 静态资源
├── scripts/                        # 🛠️ 运维与演示脚本（一键演示、数据初始化等）
└── docs/                           # 📄 项目文档
    ├── EventAlpha_MVP一周项目计划.md
    └── 目录结构说明.md
```

## 📚 目录与四层架构对应关系

| 架构层 | 对应目录 | MVP 职责 |
|--------|----------|----------|
| 📡 数据采集层 | `backend/app/collectors/` | 接入 3-5 个 RSS/公开新闻源，定时/手动采集，按 URL 或内容哈希去重，写入 `raw_news` |
| ⚙️ 事件处理层 | `backend/app/processors/` | 调用大模型/规则抽取事件标题、类型、主体、时间、摘要，合并重复来源，写入 `events` / `event_sources` |
| 🧠 推理分析层 | `backend/app/analysis/` | 生成重要性评分、影响行业与资产、因果链、正负因素、风险提示，写入 `event_analysis` |
| 🖥️ 产品服务层 | `backend/app/api/v1/` + `frontend/` | 提供事件列表/详情/卡片 JSON 接口与手动触发接口，Web 页面展示事件卡片 |

## 🗄️ 数据表与模型对应

| 数据表 | 对应模型目录 | 说明 |
|--------|--------------|------|
| `raw_news` | `backend/app/models/` | 原始新闻：来源、标题、摘要、链接、发布时间、采集时间、内容哈希 |
| `events` | `backend/app/models/` | 结构化事件：事件标题、类型、主体、时间、摘要、来源数、状态 |
| `event_sources` | `backend/app/models/` | 事件与原始新闻的多源关联 |
| `event_analysis` | `backend/app/models/` | 事件分析：重要性评分/等级、影响行业/资产、因果链、正负因素、风险提示、模型版本 |

> 上述四张表为 MVP 阶段全部数据表，对应计划第 4 节各层"建议数据表"。ORM 定义统一放在 `backend/app/models/`。

## 🔌 接口与目录对应（产品服务层）

| 接口 | 实现位置 | 用途 |
|------|----------|------|
| `GET /api/events` | `backend/app/api/v1/` | 事件列表（支持按类型、重要性、时间筛选） |
| `GET /api/events/:id` | `backend/app/api/v1/` | 事件详情 |
| `GET /api/events/:id/card` | `backend/app/api/v1/` | 事件卡片 JSON（计划第 6 节字段） |
| `POST /api/jobs/collect` | `backend/app/api/v1/` | 手动触发采集 |
| `POST /api/jobs/analyze` | `backend/app/api/v1/` | 手动触发分析 |

## 🧩 关键约定

- **统一大模型封装**：所有 LLM 调用集中在 `backend/app/services/` 的 `LLMService`，便于后续替换模型（呼应计划第 8 节技术建议）。
- **Prompt 与代码分离**：事件抽取与分析的 Prompt 模板放 `backend/config/prompts/`，做到"能配置的不写死"。
- **任务编排集中**：定时与手动触发的采集/抽取/分析流程集中在 `backend/app/jobs/`，便于 Day 6 一键演示链路串联。
- **配置外置**：新闻源、采集频率、模型参数等放 `backend/app/core/` 配置中管理。
- **版本化 API**：接口挂在 `backend/app/api/v1/`，为后续版本演进预留空间。

## 🚧 MVP 边界说明

本目录结构**严格对齐 MVP 一周计划**，仅保留四层核心链路所需的目录。以下能力属于计划第 9 节"暂缓到 MVP 之后"，**当前不创建对应目录**，待下一阶段扩展时再引入：

- 多 Agent 编排框架（`agents/`）
- 知识库与规则库（`knowledge_base/`）
- 可信度验证、市场验证、复盘学习等扩展 Agent
- 评分模型训练与评估（`ml/`）
- 容器化部署（`deploy/`）

## 📝 备注

- `frontend/app/events/[id]` 为 Next.js 动态路由目录（`[id]` 是 Next.js 约定写法，非占位符）。
- `backend/tests/samples/` 用于存放 Day 6 准备的 5-10 条可稳定复现的测试新闻样例。
- 数据库迁移使用 Alembic，初始建表脚本将在 Day 1 生成于 `backend/alembic/versions/`。
- `pyproject.toml` 在 Day 1 初始化后端项目时创建，用于管理依赖与项目元数据。
